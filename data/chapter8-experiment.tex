\section{实验准备与环境设置}

在进行模型训练和智能体评估之前，需要先完成实验所需的基础准备工作。本节从三个方面展开：首先介绍实验所使用的 PeMS08 交通数据集及其预处理流程，包括数据清洗、时间对齐、标准化和原子文件格式化四个步骤；然后说明系统的硬件部署环境和 Qwen3.5-9B 大语言模型的 vLLM 部署配置；最后给出 BIGCity 时空预测模型的训练参数设置，包括模型结构参数、优化参数和训练策略，并且对训练参数进行说明。

\subsection{实验数据集与数据预处理}

本文使用 PeMS08（Caltrans Performance Measurement System）数据集进行实验 \upcite{ref61_wang2021libcity}。PeMS08是加州交通局发布的真实高速公路交通数据集，采集于洛杉矶县区高速公路的传感器网络。本数据集包含2016年7月到8月期间170个传感器节点的交通数据，采样间隔为5分钟一次，每一个采样点记录车流量、平均车速、道路占有率这三个指标。传感器布置在多条主要高速公路的路段上，节点之间的分布情况就是实际路网拓扑结构的反映。数据集总体时间跨度为两个月，包含完整日周期和周周期变化规律，有工作日早晚高峰、周末低流量时段等典型交通模式。

原始数据用csv格式保存，每一个传感器的数据存放在一个单独的文件里。由于不同的传感器数据采集时间不一致，再加上通信故障、设备维护等各方面的因素，原始数据中存在着缺失值、异常值以及重复记录。在对模型进行训练以及智能体进行推理之前，必须先对原始数据做统一的预处理。整个预处理过程由四部分组成。

第一阶段就是数据清洗。缺失值较为普遍，某一个传感器在某段时间里因为暂时出现故障没有上报数据。对于持续时间小于3个时间步的短时缺失，用相邻时间窗口的均值来填补，即用缺失点前后两个时间步的观测值求平均来填补。对于大于30分钟的连续缺失直接标记为无效，不做插补，防止人为噪声过多影响模型训练。异常值的检测采用3σ原则，计算每个传感器流量、速度、占有率三个指标的均值和标准差，如果某一个观测值与均值的偏差大于3倍标准差，则该观测值为异常值，用相邻正常值的均值来代替。另外对于速度大于道路限速上限的极值（高速公路路段出现200km/h以上记录）、流量为负的明显错误数据也一起当作异常值来处理。

第二步就是时间对齐。不同的传感器之间虽然都以5分钟为间隔进行数据采集，但是由于各个传感器的时钟存在微小的误差以及通信延迟的影响，所以实际记录的时间戳并不是整点间隔对齐的。有的传感器记录的时间可能是 08:00:12，有的是 07:59:48。不进行对齐就直接进行时空建模，模型会把数据认为是来自不同的时间点。具体做法就是先确定整个数据集的时间范围（2016年7月1日00:00:00到2016年8月31日23:55:00），再以5分钟为步长产生统一的时间网格，共17856个时间步。将每一个传感器数据映射到时间网格上，每一个时间步取该 5 分钟区间内出现的记录平均值。如果某个传感器在某个时间步上没有记录，则该位置用0填充。经过对齐之后，所有的170个传感器都有了完全相同的17856个时间步，形成一个大小为17856×170×3的完整的时空张量。

第三步就是数据标准化。交通流量的数值范围相差很大，在不同的传感器之间，车流量有的路段可以达到上千辆每小时，有的支线路段只有几十辆每小时。直接使用原始数值进行训练，模型会把数值大的特征当作重点，忽略数值小的特征，从而影响训练的效果。为了消除量纲不同带来的影响，将所有流量、速度、占有率的数据都进行Z-score标准化处理，即均值为0、方差为1。标准化均值、方差由训练集计算得到，再用到验证集和测试集上。因此，标准化时使用训练集的统计量而不是测试集本身，防止测试数据信息泄露到训练过程中。

第四步是原子文件格式化。经过清洗、对齐和标准化之后的数据按照标准的原子文件格式进行组织和存储。\texttt{.geo} 文件存储 170 个传感器的基本信息，包括每个传感器的编号（geo\_id）、几何类型（全部为 Point）和经纬度坐标，这些坐标是后续计算路网拓扑的基础。

\texttt{.rel} 文件根据传感器之间的空间距离计算连接关系。对于任意两个传感器节点 $i$ 和 $j$，已知其经纬度坐标 $(\text{lon}_i, \text{lat}_j)$ 和 $(\text{lon}_i, \text{lat}_j)$，首先使用 Haversine 公式计算球面距离 $d_{ij}$：

\begin{equation}
d_{ij} = 2R \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta \text{lat}}{2}\right) + \cos(\text{lat}_i) \cos(\text{lat}_j) \sin^2\left(\frac{\Delta \text{lon}}{2}\right)}\right)
\end{equation}

其中 $\Delta \text{lat} = \text{lat}_j - \text{lat}_i$，$\Delta \text{lon} = \text{lon}_j - \text{lon}_i$，$R = 6371$ km 为地球半径。得到距离后，用标准差 $\sigma$ 作为缩放因子，通过高斯核函数计算节点间的相似度权重 $w_{ij}$：

\begin{equation}
w_{ij} = \exp\left( -\frac{d_{ij}^2}{\sigma^2} \right)
\end{equation}

距离越近的节点权重越大（接近 1），距离远的则接近 0。为了得到一个简洁的图网络并过滤掉关系太弱的连接，设置阈值 $\epsilon = 0.1$，只有当 $w_{ij} \geq 0.1$ 时才认为两个节点之间存在连接，记录到 .rel 文件中。这些关系数据构成了路网的邻接矩阵，作为模型的空间先验信息。

\texttt{.dyna} 文件存储所有传感器在 5 分钟间隔下的流量、速度和占有率时间序列数据，按照实体 ID 和时间双关键字排序——同一个传感器的记录放在一起，并按照时间从早到晚排列。一个完整的 \texttt{config.json} 文件描述了各字段的数据类型（比如 geo\_id 是离散 ID、traffic\_speed 是数值类型）和模型运行所需的参数（比如时间步长 300 秒、输出维度 3、从 .rel 文件中加载哪一列作为权重等）。

\subsection{硬件环境与模型部署配置}

实验的硬件环境配置如下：GPU 为一张 NVIDIA GeForce RTX 4090，显存为 24 GB；CPU 为 Intel Core i9-13900K，拥有 24 核 32 线程；系统内存为 64 GB DDR5；操作系统为 Ubuntu 22.04 LTS。整个系统运行在一台本地服务器上，所有服务和模型均部署在本地，不依赖任何外部云服务或 API 调用。这样既保证了交通数据的隐私性，也避免了网络延迟对实时推理的影响。

大语言模型采用 Qwen3.5-9B 作为智能体的推理引擎 \upcite{ref78_qwen2025techreport}。选择该模型而不是更大体量的模型（例如 70B 或 100B+ 的模型），主要是从以下几方面进行考虑。第一是硬件资源的限制。Qwen3.5-9B的9B参数在FP16精度下大约需要18GB显存，在RTX4090的24GB显存下可以正常部署运行，不需要多卡并行、模型量化、CPU offloading等额外的技术手段。如果选用大的模型，单卡不能部署，就需要使用多卡通信或者模型量化，这又会导致额外的工程复杂度以及推理延时。第二，命令执行能力的反映。Qwen3.5-9B在中文语义理解、结构化输出上比较好，可以正确地理解交通领域自然语言指令，并且能给出规范的工具调用格式。经过实际测试，在工具调用场景下它的格式正确率为100\%，比模型参数量的多少更重要。第三，上下文窗口的大小。Qwen3.5-9B支持最长20480个Token的输入长度，在ReAct循环执行时，每次循环都会把上一次的工具调用结果添加到对话历史中，如果上下文窗口太小，经过几轮交互之后就会超出限制导致历史丢失。20480 Token 的窗口大小大约能容纳8到10轮工具调用的历史记录，对大多数交通分析任务来说是足够的。

模型通过 vLLM 推理框架部署在本地服务器上 \upcite{ref79_kwon2023vllm}，对外提供与 OpenAI API 兼容的接口。vLLM 使用 PagedAttention 机制来高效管理 GPU 显存中的键值缓存。传统的注意力计算方式要为每一个请求的每一个Token分配固定的显存空间，即使某个Token的缓存没有被使用，这些空间也不能被其他的请求所复用。PagedAttention把键值缓存分成了固定大小的块（Page），按需分配、回收，从而有效地减少了显存的浪费，并且可以支持更大的批处理大小以及更高的吞吐量。部署时使用的命令如下所示：

\begin{lstlisting}[
    language=bash,
    caption={使用 vLLM 在本地服务器部署 Qwen3.5-9B},
    label={code-vllm-deploy},
    breaklines=true,
    frame=single,
    numbers=left,
    keywordstyle=\color{black},
    commentstyle=\color{black},
    stringstyle=\color{black}
]
python -m vllm.entrypoints.openai.api_server \
    --model /home/zhouzhou/public/LLM\ Library/Qwen3.5-9B/ \
    --served-model-name qwen3-5-9b \
    --tensor-parallel-size 1 \
    --dtype auto \
    --max-model-len 20480 \
    --gpu-memory-utilization 0.5 \
    --max-num-seqs 4 \
    --port 8000 \
    --reasoning-parser qwen3 \
    --enable-prefix-caching \
    --language-model-only \
    --trust-remote-code \
    --enable-auto-tool-choice \
    --tool-call-parser qwen3_coder \
    --speculative-config '{"method":"qwen3_next_mtp","num_speculative_tokens":2}'
\end{lstlisting}

部署完成后，智能体通过 HTTP 请求向本地 vLLM 服务端点发送对话消息，调用方式与 OpenAI 官方 API 完全一致。部署命令中的关键参数含义如下。

\texttt{tensor-parallel-size} 设为 1，表示使用单卡部署，不启用多卡张量并行。Qwen3.5-9B 的模型参数量为 9B，在 FP16 精度下单张 RTX 4090 的 24 GB 显存足够容纳，因此不需要通过多卡并行来分摊显存压力，也避免了多卡通信带来的额外延迟。

\texttt{gpu-memory-utilization} 设为 0.5，即 vLLM 最多使用 50\% 的 GPU 显存来分配键值缓存。预留的一半显存用于三个目的：加载模型权重（约 18 GB）、给同时运行的预测模型预留空间、以及处理突发的高并发请求。如果这个值设得太高，当其他服务同时使用 GPU 时可能出现显存不足导致的 Out of Memory 错误。

\texttt{max-model-len} 设为 20480，限制模型的最大输入输出 Token 总数。在智能体的 ReAct 循环中，每一轮都会把用户指令、系统提示词、工具调用记录和返回结果追加到对话历史中，如果上限太小，多轮交互后历史会被截断，导致模型丢失前面轮次的上下文信息。20480 Token 的窗口大约能容纳 8 到 10 轮工具调用的完整历史。

\texttt{max-num-seqs} 设为 4，限制 vLLM 同时处理的最大请求数。当多个 Agent 实例或者多次工具调用同时发送请求时，vLLM 会在显存中同时维护多个请求的键值缓存。这个参数限制了并行的请求数量，避免同时处理太多请求导致显存耗尽或者单个请求的等待时间过长。

\texttt{enable-auto-tool-choice} 和 \texttt{tool-call-parser qwen3\_coder} 两个参数配合使用，启用了 vLLM 的自动工具调用解析功能。开启后，模型在生成回答时如果判断需要调用工具，会直接输出符合工具调用规范的结构化结果，vLLM 会自动解析这些结果并返回给调用方，不需要在应用层额外编写正则表达式或者 JSON 解析代码来提取工具调用参数。\texttt{reasoning-parser qwen3} 参数则让 vLLM 能够正确解析 Qwen3.5 模型的推理过程输出，将模型内部生成的思维链与最终答案分开返回，便于后续的分析和调试。

\texttt{enable-prefix-caching} 开启了前缀缓存功能。在多次请求中，如果多个请求的系统提示词前缀是相同的（比如所有请求都使用同一份系统提示词），vLLM 会缓存这个前缀的键值计算结果，后续请求直接复用不需要重新计算，减少了重复计算的开销。\texttt{speculative-config} 启用了投机解码加速，其中 qwen3\_next\_mtp 方法在每次推理时让模型提前预测后续多个 Token 的分布，如果预测匹配则可以直接跳过多个解码步骤，在保持生成质量的同时将推理速度提升 1.5 到 2 倍。

\texttt{language-model-only} 表示只加载语言模型部分，不加载可选的视觉编码器，因为本系统只处理文本数据不需要多模态支持。\texttt{dtype auto} 让 vLLM 自动选择合适的数值精度加载模型，优先使用 FP16 以平衡显存占用和推理精度。

训练数据按照时间顺序划分为训练集（60\%）、验证集（20\%）和测试集（20\%）。训练集用于模型参数的学习，验证集用于选择最优模型和调整超参数，测试集用于最终的性能评估。这种基于时间顺序的划分方式避免了数据泄露，更接近真实应用场景下的预测任务。

下面对表中的关键参数做进一步的说明。

输入步数、预测步数都设为12，即用过去1小时（每5分钟一个步长）的数据来预测未来1小时。选择1小时的预测窗口主要是为了满足交通管理的实际需要，信号配时调整、路况预警等都需要有半小时到一小时的预见时间。同时预测步数过多会造成误差积累过大，预测结果的实用性就会降低。模型只用traffic\_flow（车流量）作为预测目标，输出维度为1。

编码器层数设为6，比一般的3层堆叠更深，可以提取更多的时空特征层次。前两层主要对相邻路段之间短期的空间依赖、近期时序变化进行捕捉，中间两层开始对更远距离的信息进行聚合，最后两层把全局的时空结构抽象出来。更深的编码器可以学习到交通流在路网中长距离传播的特征，但是也会增大训练难度。注意力头数共8个，分为4个地理注意力头、2个语义注意力头和2个时间注意力头。地理头学习相邻路段之间的空间依赖，语义头学习距离远但是功能相似的节点对之间的联系，时间头学习不同时间步之间的动态依赖关系。空间注意力窗口（s\_attn\_size）设为3，即在空间自注意力中每个节点关注其3跳范围内的邻居节点，这样可以控制注意力的计算范围同时降低复杂度。时间注意力窗口（t\_attn\_size）设为1，表示时间自注意力关注所有时间步之间的全连接依赖，不限制范围。

嵌入维度设为64，将每个时间步上每个节点的特征映射到64维的向量空间中。64维对于交通流量这种相对低维的数据是一个平衡点：维度太低会丢失特征差异信息，维度太高会增加参数量且容易过拟合。跳连维度（skip\_dim）设为256，在输出层使用较高的维度来保留更多信息。图拉普拉斯位置编码维度（lape\_dim）设为8，使用拉普拉斯矩阵的前8个特征向量来编码路网的全局结构信息。

优化器使用AdamW而非标准的Adam，区别在于AdamW将权重衰减与自适应学习率计算解耦，可以更有效地控制过拟合。权重衰减系数设为0.05，对参数较大的网络层施加更强的正则化约束。学习率初始值为0.001，调度策略采用余弦退火（CosineLR）。余弦退火的学习率按照余弦函数从初始值逐渐下降到 lr\_eta\_min（0.0001），相比StepLR的阶梯式下降，余弦退火的变化更加平滑，在训练后期可以更细致地搜索最优解。训练的前5个epoch使用预热（warmup）策略，学习率从1e-6逐渐增加到0.001，避免模型在初始阶段因为学习率过大而导致梯度震荡。

损失函数使用Huber损失，Huber损失结合了MAE和MSE的优点：当预测误差小于阈值delta（设为2）时使用MSE的平方误差形式提供稳定的梯度，当误差大于delta时切换到MAE的线性形式减少异常值的 influence。对于交通流量预测来说，大部分时刻的流量变化是平稳的（小误差场景多），但偶尔会出现由事故或管制引起的跳变（大误差场景），Huber损失正好可以兼顾这两种情况。批量大小设为16，受到GPU显存的限制。梯度裁剪阈值设为5.0，防止梯度爆炸。早停机制的 patience 设为50，如果验证集损失连续50个epoch没有下降则停止训练，避免无效训练浪费计算资源。

\section{时空模型预测能力评估}

本节用 PeMS08 数据集来评价系统中使用的大城市时空预测模型BIGCity的预测性能。评价从三个方面进行，第一是选择评价指标及基线模型，确定了用来衡量预测精度的三个指标（MAE、MAPE、RMSE），并且引入了HA、ARIMA、SVR、STGCN、DCRNN、GWNET六种有代表性的基线模型进行比较；第二是模型训练过程中收敛性的分析，用训练损失和验证损失的变化曲线来判断模型学习效果以及泛化能力；第三是在测试集上进行预测结果的对比分析，从各个方面对BIGCity比基线模型提高的幅度及原因进行考察。经过以上三个层次的递进式评价，就可以对模型的预测能力有一个完整的认识。

\subsection{评价指标与基线模型}

实验用三个交通预测领域常用的评价指标来评价模型的预测性能。每一个指标从不同的角度来衡量预测的准确性，综合使用可以比较全面地反映模型的表现。
第一个指标是平均绝对误差（MAE），即预测值和真实值之差的平均值，记为：

\begin{equation}
\text{MAE} = \frac{1}{n} \sum_{i=1}^{n} |y_i - \hat{y}_i|
\end{equation}

MAE表示的是预测误差的总体大小，量纲和原始数据一致，在交通流量预测中单位是车辆数/小时，数值越小说明预测越准确。它具有对所有的误差都给予同样的权重，不会因为个别大的误差点而大幅度偏离。当大多数时间点的预测接近真实值的时候，MAE就会比较低；但是如果有少数离群点，MAE也不会被拉得太高。

第二个是均方根误差（RMSE），对误差先平方再取均值后开方：

\begin{equation}
\text{RMSE} = \sqrt{\frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2}
\end{equation}

RMSE和MAE最大的不同就是它对于较大的预测误差有更高的惩罚权重。因为误差平方后会变大，一个偏离较大的预测值就会大大提高RMSE。因此RMSE更适合用来评价模型的稳定性，如果RMSE远大于MAE，那么模型中就存在着一些预测效果特别差的时间点或者路段。交通流量预测中，出现这种情况一般是在交通模式发生突变的时候（比如发生事故之后），RMSE会放大这些问题，从而找到模型存在的不足之处。


第三个是平均绝对百分比误差（MAPE），计算预测值与真实值之间的相对误差百分比：

\begin{equation}
\text{MAPE} = \frac{1}{n} \sum_{i=1}^{n} \left|\frac{y_i - \hat{y}_i}{y_i}\right| \times 100\%
\end{equation}

MAPE消除了量纲的影响，在不同的量级数据之间可以进行比较。流量大路段和流量小路段之间MAE不能直接比较，但是MAPE可以。它的缺点是当真实值接近于零的时候，比率就会变得很大，所以一般只适用于传感器工作时段内（即流量不为零的时间点）的计算。

为了对模型进行全面的评价，选择出六个有代表性的基线模型，分别属于传统的统计方法、深度学习的方法。

HA（历史平均法）是最简单的一种基准方法，用相同时间段的历史平均值作为预测结果。预测周一早上8点的流量，用过去所有周一早上8点的观测值的平均。HA 不考虑任何交通流的波动性、随机性，预测结果是一条平滑的曲线，不能反映真实的交通变化。一般被用作衡量其它模型提升幅度的最低基线。

ARIMA（自回归移动平均模型）是经典的时间序列统计方法 \upcite{ref75_williams2003arima}。它通过分析序列的自相关函数和偏自相关函数来确定模型阶数，用过去观测值的线性组合来预测未来值。ARIMA的优点有成熟的统计学理论基础，在小样本、稳定序列上表现好。但是交通预测中ARIMA只能对单条时间序列进行独立建模，不能利用路网中其它路段的信息，也不能处理交通流中的非线性模式。

SVR（支持向量回归）属于传统的机器学习算法，利用核函数把低维数据映射到高维空间，在高维空间里找到一个超平面去拟合数据。SVR的优势是能很好地处理非线性关系，在小样本情况下表现更好。但是SVR只能对一条时间序列进行建模，不能利用路网的空间拓扑结构，并且超参数的选择会对最终的效果产生较大的影响。

STGCN（时空图卷积网络）是较早将图卷积网络引入交通预测的工作之一 \upcite{ref7_yu2018stgcn}。它同时包含两个维度的建模模块——用图卷积捕捉路网的空间依赖关系，用一维时序卷积捕捉时间依赖关系，最后将两者的输出整合到一个统一的框架中。STGCN 证明了在交通预测中引入图结构来建模路网拓扑的有效性，是后续时空融合模型的重要基础。

DCRNN（扩散卷积循环神经网络）采用了与 STGCN 不同的技术路线 \upcite{ref8_li2018dcrnn}。它将交通流在路网上的传播建模为扩散过程，使用双向扩散卷积代替标准的图卷积来捕捉空间依赖，同时使用门控循环单元作为循环结构来建模时间维度上的演化规律，并采用序列到序列的编码器-解码器结构进行多步预测。DCRNN 提出了一种融合 RNN 和 GNN 的时空建模范式，对后续工作影响较大。

GWNET（Graph WaveNet）引入了自适应邻接矩阵和扩张因果卷积两个关键技术 \upcite{ref9_wu2019graphwavenet}。自适应邻接矩阵让模型可以通过随机初始化的节点嵌入自行学习节点之间的空间依赖关系，而不需要依赖预先定义的路网拓扑。扩张因果卷积通过逐层增加感受野来捕捉长时间依赖，同时保持线性时间复杂度。GWNET 有效地解决了传统 GNN 方法只能使用固定邻接矩阵的问题，在多个交通数据集上达到了当时的领先水平。

\subsection{模型训练收敛性分析}

在训练过程中，模型的训练损失和验证损失随迭代步数的变化趋势反映了模型的学习能力和泛化能力。实验记录了每轮训练过程中训练集和验证集上的 Huber 损失值，横轴表示训练的迭代步数（step），每个 step 对应一个 batch 的前向传播和反向传播。训练过程共进行了约 13 万步，覆盖了完整的 200 个 epoch。训练总耗时约 3 小时，平均每个 epoch 需要约 650 步，每步处理一个 batch 的 16 个样本。

从训练损失曲线中可以观察到两个明显的阶段。第一阶段是剧烈下降期，大约在 0 到 3000 步之间（对应前 2 个 epoch）。训练损失从初始值 176.9 迅速下降到 31.1，下降幅度达到 82\%。这个阶段模型在快速学习交通数据的基本分布特征，包括传感器节点的空间位置关系、时间序列的周期性规律（如早晚高峰模式）以及交通流量的基本统计特性。曲线的波动较大，这是 AdamW 优化器在学习率处于预热阶段之后的最高值附近进行参数剧烈调整的正常现象。

第二阶段是缓慢收敛期，从 3000 步一直延续到训练结束。损失值从 31.1 缓慢下降到最终的 23.66，下降幅度约 24\%。这个阶段模型开始学习更复杂的时空依赖关系，比如不同路段之间流量传播的延迟特性、拥堵在路网中的扩散模式等。余弦退火调度策略在这个阶段发挥作用，使学习率按照余弦函数的形状逐渐减小，优化器从大范围的参数搜索逐渐过渡到局部区域的精细调整。曲线呈现出小幅的锯齿状波动，幅度在 1-2 之间，这是不同 batch 之间数据分布差异造成的正常现象。整个训练过程中没有出现损失反弹或震荡发散的情况，说明学习率设置合理，优化器能够稳定地收敛。

从验证损失曲线可以看出，前 8 个 epoch（约 0 到 10000 步）下降最为剧烈，从 212.7 阶梯式骤降到 29.7。验证损失在每个 epoch 结束时计算，因此呈现出阶梯状下降的特征。具体来说，第 1 个 epoch 结束时降到 176.6，第 2 个 epoch 降到 155.8，第 3 个 epoch 降到 122.6，第 4 个 epoch 降到 106.8，第 5 个 epoch 降到 82.4，第 6 个 epoch 降到 46.8，第 7 个 epoch 降到 29.7。前 8 个 epoch 就完成了约 86\% 的损失下降（从 212.7 降至 29.7），说明模型在初期的学习效率最高，能够在极少的迭代次数内掌握交通数据的核心规律。验证损失的初始值 212.7 高于训练损失的 176.9，这是因为验证集的数据分布与训练集存在差异，模型在初始阶段对未见过的数据预测能力较弱，符合预期。

从第 8 个 epoch 之后，验证损失进入缓慢收敛阶段，从 29.7 逐步下降到最终的 25.57，下降幅度约 14\%，远小于前期的下降幅度。在这个阶段验证损失的下降速度与训练损失基本同步，说明模型在继续学习有效特征而非过度拟合训练数据。在第 50 个 epoch 左右，验证损失下降至约 26.5，进入了一个较长的平台期。由于早停机制的 patience 设为 50，模型在验证损失不再下降时不会立即停止，而是继续训练以寻找更优的参数空间。从曲线可以看出，在 100 到 150 个 epoch 之间，验证损失有小幅波动但基本保持平稳，直到约 160 个 epoch 后再次出现轻微下降，最终收敛到 25.57。

从表中可以看出，不同类别的模型在三个指标上表现出明显的层次差异。第一层次是传统统计和机器学习方法（HA、ARIMA、SVR），它们的 MAE 在 22.32 到 25.10 之间，MAPE 在 14.47\% 到 15.80\% 之间，RMSE 在 33.83 到 36.50 之间。HA 的 MAE 为 22.32，说明单纯用历史平均很难应对交通流的随机波动，因为交通数据在不同日期之间的差异往往大于同一时间点的周期规律。ARIMA 的 MAE 为 25.10，甚至比 HA 还差，这是因为 ARIMA 的线性假设不适合 PeMS08 这类具有非线性突变特征的交通流量数据。SVR 的 MAE 为 23.25，虽然能够通过核函数处理部分非线性关系，但仍然受到单变量独立建模的限制。这三类方法的共同问题在于它们只能对单个时间序列独立建模，无法利用路网中其他路段的空间信息，因此在三个指标上都表现不佳。

第二层次是基于图神经网络的方法（STGCN、DCRNN、GWNET），它们的 MAE 在 15.06 到 18.19 之间，相比传统方法有明显的提升。STGCN 的 MAE 为 17.84，比最好的传统方法 SVR 降低了约 23\%，说明引入图卷积来建模路网拓扑结构确实有效。DCRNN 的 MAE 为 18.19，略高于 STGCN，可能是因为 PeMS08 的路网结构相对简单，扩散卷积的复杂建模能力带来的收益有限。GWNET 的 MAE 为 15.06，相比 STGCN 又降低了约 16\%，这得益于其自适应邻接矩阵机制——它不依赖预先定义的路网拓扑，而是让模型自行学习节点之间的依赖关系，可以发现一些路网拓扑中没有直接连接但流量变化高度相关的节点对。

BIGCity 的 MAE 为 13.58，相比第二层次中最好的 GWNET 降低了约 10\% \upcite{ref62_yu2025bigcity}，MAPE 降至 9.05\%，RMSE 降至 23.51，三项指标均为最优。提升来自于三个方面的设计。第一种就是用动态空间自注意力机制取代了固定邻接矩阵。在传统的图卷积方法里，路段之间的空间依赖是固定的，邻接矩阵一旦确定就不会改变。但是实际交通中相邻路段之间的相互影响是动态的，在早高峰期间上游到下游的影响比较大，平峰期间则非常微弱。动态自注意力会根据当前的交通情况来动态计算各个路段之间关系的权重，从而更好的反映真实的关系。第二是长、短距离掩码联合使用。短距离掩码（地理掩码）使模型只考虑路网上直接相邻的路段，长距离掩码（语义掩码）用DTW算法找出流量变化模式相似的远距离节点，即使它们在路网上相距很远。将两者结合起来，就可以在局部传播的基础上，依靠远处节点的相似性进行预测。第三为延迟感知模块。交通拥堵在路网中传播不是瞬时的，是需要时间的，一段路段出现拥堵之后，大约需要 5 至 15 分钟才会波及到下游路段的交通状况。延迟感知模块用k-Shape聚类提取历史交通模式，把它们整合到注意力计算里，使得模型可以明确地建模传播延迟，从而得到更加贴近真实的交通物理规律的结果。

从 RMSE 的角度来看，各方法的差异趋势与 MAE 基本一致，但 RMSE 的数值普遍比 MAE 高出约 1.5 到 1.7 倍。例如 BIGCity 的 MAE 为 13.58，RMSE 为 23.51，RMSE/MAE 的比值约为 1.73，与其他模型处于同一水平。这说明 BIGCity 的误差分布没有出现极端的大误差点，预测结果的稳定性较好。

\section{Agent指令解析与执行能力验证}

前两节验证了时空预测模型的预测精度，但系统最终的价值体现在智能体能否准确理解用户指令并正确调用工具。本节从指令理解、工具调度和端到端执行三个维度对智能体进行系统性评估。实验基于批量测试框架，在相同的本地部署环境中逐条读取测试用例，调用编译好的 LangGraph 工作流，记录每条用例的完整推理过程和最终输出结果。大模型使用本地 GPU 服务器上通过 vLLM 部署的 Qwen3.5-9B。底层工具链包括态势查询接口、历史趋势查询接口和 BIGCity 流量预测接口。

\subsection{指令理解与意图识别准确率评估}

评估从四个方面展开。第一是意图识别准确率，智能体能否根据用户指令正确选择三个工具之一，或在不需要工具时直接回复。第二是工具调度正确性，智能体能否正确提取实体 ID 和时间参数，特别是时间参数使用了中文口语、阿拉伯数字、斜杠分隔和点分隔等多种格式。第三是报告生成质量，智能体在收到工具返回的原始数据后能否组织出条理清晰的分析报告。第四是异常处理鲁棒性，遇到传感器 ID 越界、时间超出范围等情况时能否给出有意义的错误提示。

测试用例共 37 条，按照任务类型和难度分为七类。第一类是基础查询，共 8 条，用户指令涉及单个传感器和单个时间点，目的是验证智能体最基本的意图识别和参数提取能力，比如“帮我查下 1 号传感器在 2016 年七月一日上午十点的流量”。第二类是深度分析，共 11 条，在基础查询之上要求智能体获取当前数据的同时拉取历史趋势，给出综合研判，比如“能分析一下 2 号探头在 2016.7.1 下午五点半那会儿的交通情况吗”。第三类是流量预测，共 8 条，要求智能体调用预测模型获取未来一段时间内的流量变化趋势，比如“预测一下 3 号传感器从 2016 年 7 月 2 日早上八点开始未来半小时的车流”。第四类是多工具协同，共 6 条，指令中同时包含多个传感器和多个时间点，智能体需要在一次对话中依次调用不同的工具完成多阶段任务，比如“先查 7 号探头凌晨的数据，再分析 8 号上午的情况，最后预测 9 号晚上的车流”。第五类是无工具调用，共 1 条，用户输入的是问候语而非查询指令，验证智能体能否正确判断不需要调用工具而直接回复。第六类是异常输入，共 2 条，输入包含超出范围的传感器编号，验证智能体在数据不存在时的降级处理能力。第七类是密集并行，共 1 条，指令中同时包含三个传感器和三个时间点共九个查询维度，验证智能体在极端多参数场景下的并行调度能力。用例设计覆盖了全部三个工具类型，时间表述包括了中文书面语（七月一日）、带分隔符的数字（7.3、2016/7/2）和相对时间（昨天）等多种格式。表 \ref{tab:test-cases} 列出了七类用例的详细分布和典型示例。

本节从七类用例中选择有代表性的样本，展示智能体完整的推理过程以及执行链路。覆盖的用例类型有基础查询、深度分析、流量预测、多工具协同、异常处理，每个类型选择一条典型的用例，从用户输入开始，一步一步地展示意图识别、工具调用、结果返回、报告生成的过程。每一个场景的描述都会先解析用户自然语言指令的内容，再说明智能体是如何把指令映射成具体的工具调用序列（包括并行调用和多步推理），工具执行节点又是如何调用后端接口获取原始数据，最后大模型又是如何将返回的结构化数据整合成最终的分析报告的。最终大模型输出的分析报告用Markdown格式进行结构化的呈现，包括标题、数据表格以及分析结论等。本节通过执行链路图来直观地展示出智能体在每一个决策中所作出的选择以及 LangGraph 状态图循环的过程，从而了解信息从用户输入、工具节点到大模型最后输出整个流转过程。

\section{实验总结}

本章从三个方面对系统进行了全面的实验验证。首先是时空预测模型 BIGCity 的预测精度评估，在 PeMS08 数据集上与六个基线模型进行了对比，并从训练收敛性和测试集表现两个角度展开分析。其次是智能体的指令解析与执行能力验证，通过 37 条覆盖七类场景的测试用例检验了意图识别、时间格式解析和多工具协同调度的正确性。最后是异常处理与鲁棒性方面的表现。

在时空预测模型评估方面，BIGCity 在 PeMS08 数据集上取得了 MAE 13.58、MAPE 9.05\%、RMSE 23.51 的预测精度，三项指标均优于 HA、ARIMA、SVR、STGCN、DCRNN 和 GWNET 等六个基线模型。相比传统统计方法（HA、ARIMA、SVR），BIGCity 的 MAE 降低了约 40\%，说明深度时空建模相比单变量时间序列分析具有明显的优势。相比图神经网络方法（STGCN、DCRNN、GWNET），BIGCity 的 MAE 降低了约 10\% 到 24\%，提升主要来自动态空间自注意力、长短距离掩码和延迟感知模块三方面的设计。在训练收敛性方面，模型经过 200 个 epoch 的训练后，训练损失和验证损失分别收敛到 23.66 和 25.57，两条曲线始终保持接近，没有出现过拟合的迹象。前 8 个 epoch 就完成了约 86\% 的损失下降，说明模型结构设计和优化策略是高效的。

在智能体指令解析与执行能力验证方面，37 条覆盖七类场景的测试用例全部正确识别。智能体能够正确区分基础查询、深度分析、流量预测、多工具协同和无工具调用等多种任务类型。时间格式解析覆盖了中文书面语、数字+点分隔、斜杠分隔、ISO-8601 和相对时间五种自然语言格式，全部解析成功。工具参数提取在 36 条需要工具调用的用例中均正确，在多工具协同场景中能够从包含多个实体和时间点的复合指令中准确提取参数。典型交互场景的执行结果进一步验证了智能体在多步推理中保持上下文一致性、自动对比分析、生成结构化报告的能力。

在异常处理与鲁棒性方面，智能体对传感器 ID 越界、查询时间超出数据集范围、历史数据不足等异常情况均做出了有意义的降级处理，如实告知用户错误的可能原因并提供后续建议，全程未出现系统崩溃或模型产生幻觉的情况。实验中也发现了一个需要改进的问题：当传感器编号落在 1 到 31 的合法日期范围内且紧邻时间描述词出现时，大模型可能将传感器编号误解为日期，导致后续工具调用使用错误的日期参数。后续工作可以从提示词工程和状态图设计两个方向解决这一问题。

综合来看，实验结果验证了系统架构设计的有效性。BIGCity 时空预测模型提供了高精度的交通预测能力，基于 ReAct 范式和 LangGraph 框架的智能体流程实现了准确的自然语言指令理解和工具调用，慢思考与快反应相结合的双层架构保证了系统在复杂交通场景下的稳定运行。

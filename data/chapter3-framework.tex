\chapter{系统架构与技术路线}

\section{总体研究方案}

本研究采取”数据驱动感知、大模型状态图调度、多工具并行执行”的总体方案。

首先，依托 PeMS08 交通传感器网络的大规模时空序列数据，经过数据清洗与标准化处理，构建结构化的交通态势特征库，为后续的 Agent 推理提供高保真的感知输入。接着，以本地部署的 Qwen3.5-9B 大语言模型作为智能体的推理引擎，结合精心设计的系统提示词，实现对复杂交通任务指令的意图拆解。针对交通任务的强时效性与多并发特点，本研究基于 LangGraph 框架构建了状态图（StateGraph）循环执行引擎。Agent 能够在单次推理中生成多个独立的工具调用指令，由工具执行节点并行分发给底层服务。最后，将大模型的语义理解能力与 PDFormer 时空预测模型深度集成，构建一个集流量查询、历史溯源、时空演化预测于一体的闭环原型系统，为城市交通管理决策提供智能化支撑。


\section{技术路线}

本研究的技术路线自下而上划分为五个层级：感知层、认知层、决策层、执行层和应用层。感知层重点解决多源异构交通数据的清洗、对齐与特征组装问题；认知层基于本地化部署的大模型实现自然语言指令的语义解析与子任务拆解；决策层引入状态机（State Machine）思想，基于图结构编排智能体的思考与工具调度逻辑，通过双重兼容的解析机制保障并行工具调用的可靠性；执行层负责具体领域模型的调用，包括历史趋势的深度分析与基于时空图卷积的流量预测；应用层侧重于工程落地，利用 FastAPI 与 SQLite 构建具备高并发响应与时序记忆能力的后端微服务。通过这一分层架构设计，系统实现了逻辑控制权与计算执行权的有效分离，确保了复杂交通长尾场景下的鲁棒性与可扩展性。

\subsection{感知层}

感知层作为系统的底层数据基座，重点在于解决多源异构交通数据的清洗、集成与时空对齐问题。实际交通场景中，传感器数据往往来自不同采集设备与通信协议，存在时间戳不同步、字段缺失与格式不一致等挑战。本研究首先对原始流数据进行统一的标准化处理与缺失值插补，继而根据路网拓扑结构将碎片化的点位流量映射至全局图结构特征矩阵中。通过设计特定的数据滑动窗口机制，将连续的时间序列截取为符合下游模型输入要求的离散时间步特征矩阵。这一过程不仅消除了多源数据不一致与传感器缺失带来的噪声干扰，更为后续预测引擎与智能体分析提供了标准化、高质量的时空感知输入。

\subsection{认知层}

认知层发挥系统”大脑”的作用，通过预训练大语言模型实现对交通管理意图的深层次解析。系统选用 Qwen3.5-9B 作为核心推理引擎，并设计了结构化的系统级提示词（System Prompt）。提示词中明确定义了三个可用核心工具的接口规范与选择原则：仅查询时使用 simple\_query，需要分析研判时使用 deep\_analysis，需要预测时使用 predict\_traffic。提示词同时约束了数据截取与展示规范，例如预测结果默认返回未来 1 小时共 12 个时间步，若用户指定更短时间范围则由 Agent 自行在报告中截断。当用户指令进入认知层后，模型能够自动识别长文本指令中的实体 ID 与时间参数，将宏观交通任务拆解为细粒度的子任务序列，从而为决策阶段的并发工具调度奠定认知基础。在工具调用格式上，系统采用 XML 标签协议：Agent 可在单次回复中输出多个独立的 \texttt{<tool\_call>} 标签块，每个标签内使用 \texttt{<function=...>} 子标签指定工具名，使用 \texttt{<parameter=...>} 子标签传递参数。

\subsection{决策层}

决策层是连接认知意图与底层执行的关键桥梁。本层级引入 LangGraph 框架构建基于有向循环图（StateGraph）的状态流转机制。系统定义了两个核心图节点：大模型推理节点（Agent Node）与工具执行节点（Tool Execution Node）。Agent Node 负责调用 LLM 生成工具调用指令，Tool Execution Node 基于 LangGraph 预置的 ToolNode 实现，负责接收工具调用列表并实际执行。两节点之间通过条件路由边连接：条件边检查 Agent Node 输出消息的 \texttt{tool\_calls} 属性是否非空。如果包含有效的工具调用，则流转至 Tool Execution Node，执行完成后回到 Agent Node 继续推理。如果为空，说明模型已完成分析，触发终止条件 END，结束本次推理循环。

针对大模型在生成工具调用时可能出现的格式偏差问题，Agent Node 内部集成了双重兼容的解析机制。优先使用 LangChain 的 \texttt{bind\_tools} 通道，让大模型直接生成符合 OpenAI 函数调用规范的结构化工具调用数据。如果原生通道未产生工具调用，而模型输出的文本中又包含 \texttt{<tool\_call>} 标签，节点会自动切换到正则回退模式：首先用非贪婪正则表达式 \texttt{<tool\_call>(.*?)</tool\_call>} 提取每个标签块的内容，然后在块内匹配 \texttt{<function=...>} 和 \texttt{<parameter=...>} 子标签以提取工具名和参数值，最后构造等价的工具调用对象并替换原响应消息。这种双重机制兼顾了标准 API 通道的可靠性和原生 XML 格式的兼容性，避免了因单次格式偏差导致整个推理流程中断。

\subsection{执行层}

执行层是系统闭环能力的落脚点，由三个专业化的领域工具构成。每个工具均以统一的函数签名（\texttt{entity\_id} 与 \texttt{time}）对外暴露，便于 Agent 进行标准化调用：

\textbf{（1）态势查询工具（simple\_query）。}通过调用后端 RESTful 接口获取指定传感器在特定时刻的流量、速度与占有率等瞬时交通状态，适用于点位级的实时快照查询。

\textbf{（2）深度分析工具（deep\_analysis）。}在获取当前时刻数据的基础上，额外拉取该传感器过去 3 小时的连续历史趋势序列，为 Agent 提供具备时间纵深的多维分析素材，适用于交通态势的成因追溯与趋势研判。

\textbf{（3）时空预测工具（predict\_traffic）。}该工具在执行时会自动完成全局路网特征矩阵的组装：首先遍历全路网所有传感器节点，从后端记忆库中分别拉取各自过去 1 小时（共 12 个时间步）的历史流量序列；随后按时间戳对齐并聚合为完整的时空特征矩阵；最后将矩阵序列化后发送至后端的时空预测引擎（如 PDFormer 架构）进行推理。预测引擎返回未来 1 小时（每 5 分钟一个预测步，共 12 步）的全路网流量预测结果，工具从中提取目标节点的预测序列并以结构化 JSON 报文返回给 Agent。通过将深度学习模型的黑盒预测结果转化为可解析的定量决策依据，执行层完成了从原始感知数据到智能分析结论的实质性转化。

\subsection{应用层}

应用层聚焦于原型系统的工程落地与交互闭环。系统后端基于 FastAPI 框架开发，以微服务架构承载高并发的请求解析与 Agent 调度，并利用 SQLite 构建轻量级、具备时序查询能力的本地记忆库。通过封装友好的 RESTful 接口，应用层不仅负责综合呈现包含实时态势监控与未来演化预测的最终分析报告，还支持在真实多维度的交通运维场景中开展交互测试，充分验证该协同架构在长尾并发任务下的泛化性能与实用价值。


\section{技术开发环境与实现工具}

\begin{itemize}
    \item \textbf{开发语言}：Python 3.10
    \item \textbf{后端服务框架}：FastAPI
    \item \textbf{大语言模型底座}：Qwen3.5-9B
    \item \textbf{Agent 调度与控制框架}：LangChain / LangGraph (状态图范式)
    \item \textbf{时空交通预测模型}：PDFormer（基于图卷积的时空预测架构，实验验证采用 PEMS08 数据集）
    \item \textbf{数据库管理}：SQLite
\end{itemize}
